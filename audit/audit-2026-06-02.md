# codebase audit — 2026-06-02

## scope

Full `ac` repo. Audited: the 4-crate Rust workspace under `ac-rs/crates/`
(`ac-core`, `ac-daemon`, `ac-ui`, `ac-cli`, ~45k LOC) plus the standalone Python
companion package `ds/`. Three specialist perspectives assembled:

- **architect** — module boundaries, dependency graph, invariants, ZMQ surface
  (`audit/architect-raw.md`, 2026-05-27).
- **ux** — every stdout/stderr surface across the workspace, format and label
  consistency vs the `ac` CLI baseline (`audit/ux-audit-2026-05-27.md`).
- **qa** — test-coverage map + standards conformance vs 7 reference PDFs;
  build state `cargo test --workspace` → 680 passed, 0 failed, 3 ignored
  (`audit/qa-audit-2026-05-27.md`).

Out of scope: runtime/hardware-in-the-loop verification on the test rig; `ds`
Claude-API behaviour beyond static read; performance/latency. Read-only audit —
no source modified, no issues created.

Specialist sub-reports were produced 2026-05-27; this consolidation supersedes
`audit/audit-2026-05-27.md` and re-frames findings around the cross-cutting view.

## executive summary

The codebase is structurally healthy: a clean acyclic dependency graph with one
shared lib, a strong test suite (680 green), and exemplary coverage on the DSP
core (H1 transfer estimator, BS.1770-5 loudness, weighting networks). The
weaknesses cluster in two places. First, the **ZMQ wire schema** is the single
most brittle thing in the tree — defined three times (daemon inline `json!()`,
typed ac-ui structs, untyped ac-cli `Value`), with no shared type and no
producer↔consumer test, so a field rename fails silently at runtime. Second, a
band of **THD+N correctness, labelling, and test-coverage gaps** all reinforce
each other: the denominator is the fundamental (should be total signal), the
display lacks a reference, and every test feeds near-pure sine so the bug is
structurally invisible. Documentation drift (stale module map, a misnamed "H1 /
Müller-Massarani" invariant) is real but cosmetic next to those two. Nothing
found is alarming; the foundation is sound and the fixes are well-scoped.

## cross-cutting findings

### [cross-cutting] ZMQ schema is triple-defined AND has no producer↔consumer test
**areas:** architect + qa
**finding:** The wire schema lives in three places with no shared type — daemon
emits inline `json!()`, ac-ui mirrors it in typed serde structs
(`ac-ui/data/types.rs`), ac-cli parses untyped `serde_json::Value`. Agreement is
manual, with `ZMQ.md` (51 KB) as the only authority, and Tier 2 / streaming
frames carry no `schema_version` at all. Independently, qa found there is **no
round-trip test** that ac-ui deserializes the exact JSON ac-daemon emits for the
monitor sidecar frames (`momentary_lkfs`, `integrated_lkfs`, `dBTP`, THD).
**why it matters:** This is the same defect seen from two angles. A renamed field
on either side compiles clean, passes CI, and fails only at runtime in the UI —
the structural brittleness (architect) and the missing safety net (qa) compound:
nothing catches the break before a user does. Any future issue touching frame
fields is high-risk.
**suggested first step:** Add one ac-daemon→ac-ui JSON round-trip test for the
monitor sidecar frames now (cheap, catches drift immediately). Then hoist the
frame structs into `ac-core` so daemon serializes and ui/cli deserialize the same
type, and add a protocol version to the Tier 2 data envelope.

### [cross-cutting] THD+N is wrong, unlabelled, and untestable — all at once
**areas:** qa + ux
**finding:** qa: the THD+N ratio divides residual by the **fundamental**
(`thd.rs:118,107`), but AES17-2020 §6.3.1 and IEC 60268-3 §15.12.3.2 (the cited
clause) reference the **total signal level** — wrong as distortion rises — and
every existing test feeds pure/near-pure sine, so the divergence is structurally
untestable; the one test that could catch it asserts nothing (`thd.rs:308`,
`let _ = result;`). Separately, the standard prefers **dB** for digital ratios
while the code emits `%`. ux: the `THD+N%` column carries **no reference label**
(`io.rs:168`) and the dB form — the readable one at low distortion — is never
shown on the CLI.
**why it matters:** The number is computed wrong, displayed without its frame,
and guarded by a test that can't fail. A DUT with several-percent THD+N reads
low, and nobody finds out. The correctness fix and the display fix touch the same
value and the same standards question (dB vs %), so doing them separately risks
relabelling around a still-wrong number.
**suggested first step:** Decide the governing standard for the digital path
(AES17-2020 → dB) in one place, then fix the denominator to total signal level
and add a high-distortion-plus-noise test pinning a known THD+N value — only
after that adjust the CLI label to match.

### [cross-cutting] stale module map rediscovered by all three specialists
**areas:** architect + qa + ux
**finding:** The spec/onboarding module model (`ac::estimator`, `thd_tool::*`,
`ds/src/session.rs`, `level.rs`, `signal.rs`) does not match reality (H1 =
`ac-core/visualize/transfer.rs`; THD = `ac-core/measurement/thd.rs`; `ds` is
Python, no `thd_tool` crate). All three specialists independently hit this and
had to re-map before working. The architect also flags the related invariant
**"H1 matches Müller-Massarani"** as misstated — the live path is Welch-H1, the
sweep path is Farina (correctly cited in `sweep.rs`), and no Müller/Massarani
reference exists in code.
**why it matters:** Every agent and every new dev pays the same re-mapping tax,
and a misnamed invariant actively invites someone to "fix" correct code toward
the wrong derivation. Low severity per finding, but it taxes all future work
across all three areas — the definition of cross-cutting.
**suggested first step:** Refresh the module map in the spec/onboarding docs to
the real `ac-rs/crates/` layout, and correct the invariant wording to cite Welch
(live H1 = Gxy/Gxx) and Farina (sweep) explicitly.

### [cross-cutting] timestamp/filename unification crosses the implicit ds file contract
**areas:** ux + architect
**finding:** ux found three coexisting timestamp formats and no ISO-8601 stamp on
any CLI run; the owner-approved fix unifies every surface and filename on UTC,
which **changes on-disk filenames**. architect found that `ds` couples to `ac`
purely through on-disk file layout (`ds/files.py:9`, `ds/context.py:91` scan the
session dir for `.csv`/`.png`) with **no schema and no test** — changing output
filenames breaks `ds` context summaries with no compile error.
**why it matters:** A display-polish change (ux) reaches across an undocumented,
untested integration boundary (architect). The timestamp cutover looks
display-only but can silently break `ds`.
**suggested first step:** Before the filename cutover, document the session-dir
contract (or expose an `ac` command `ds` calls), then sequence the timestamp
unification last, coordinated with the daemon + ds owners — existing files keep
old names, only new writes change.

## architect findings

Reality vs spec: a 4-crate cargo workspace (`ac-core`, `ac-daemon`, `ac-ui`,
`ac-cli`) plus standalone Python `ds/`. ~45k LOC.

**Module boundaries — solid.** Clean acyclic dependency graph, single shared lib:
`ac-core ← {ac-daemon, ac-ui, ac-cli}`. No circular deps, no client depends on
another. `ds/` is fully outside the cargo workspace and couples to `ac` only via
on-disk file layout, not the wire protocol. One smell: wire-frame construction
(daemon inline `json!()`) and its typed mirror (`ac-ui/data/types.rs`) sit in two
crates with no shared type.

**Invariant audit:**

| invariant | enforced | notes |
|---|---|---|
| ZMQ schema single-sourced | ✗ | Triplicated; agreement manual; `ZMQ.md` is the only authority. |
| no freq-dependent level ref | ✓ | `shared/reference_levels.rs` + `conversions.rs` scalar; mic curve separated, applied post-measurement. |
| H1 matches Müller-Massarani | ✗ | **Invariant misstated.** Live = Welch-H1 (Gxy/Gxx); sweep = Farina (cited correctly in `sweep.rs`). No Müller/Massarani in code. |
| thd_tool standalone | ✓ (N/A) | No such crate; THD is a pure lib module, no runtime coupling. |

**Interface surface.** ZMQ REP ctrl `:5556`, PUB data `:5557`; frames are
`<topic> <json>`. Only Tier 1 `measurement/report` carries `schema_version`
(=3); all Tier 2 / streaming frames unversioned. ac-ui uses `#[serde(default)]`
~31× for additive forward-compat (renames/removals still break). CLI clap
subcommands are consistent; `ds` has a separate intentional Python CLI surface.

**Structural risks (ranked):**
1. ZMQ schema triple-defined, no shared type, Tier 2 unversioned — most brittle.
2. Stale architecture map vs reality.
3. Misnamed H1 invariant.
4. `ds`↔`ac` file-layout coupling is implicit — no schema, no test.

**Solid:** crate graph (no refactor needed), scalar level reference + separated
mic curve, the Farina sweep math + citation, `#[serde(default)]` discipline. No
significant dead code in the level-ref/conversion paths.

## ux findings

CLI output is structured, decimal-aligned, and unit-aware in most places — the
foundation is sound. It misses the `ac` CLI baseline on three mandatory fields,
carries decorative borders the spec forbids, and is inconsistent on dB precision
and reference labels across tools.

**Baseline deviations (high severity):**
- **No ISO-8601 timestamp on any run** — exists only in filenames + embedded
  report JSON. `io.rs:159 timestamp()` is filename-only.
- **No duration / averaging window shown** — only the *requested* sweep duration
  is echoed; never elapsed or averaging count.
- **Noise floor hidden** — `noise_floor_dbfs` is measured and written to CSV
  (`io.rs:14`) but never shown on screen. The most diagnostic figure is withheld
  from the eye while `Average THD` (a weaker aggregate) gets a summary line.

**Consistency / label gaps (med–low):**
- Decorative borders — `"=".repeat(62)` + `─` rules (`io.rs:92,94,139`); spec says
  prefer whitespace, never box.
- `THD+N%` column has no reference (`io.rs:168`); dB-re-fund form never shown.
- dB precision varies (`.1` sweep/plot, `.2` dmm/calibrate, `.8` V setup).
- Inline `[CLIP]`/`[AC]` at row end; baseline wants warnings on their own line.
- All-caps `[PASS]`/`[FAIL]`/`SUMMARY` — shouty, off-register.
- Three timestamp formats coexist; TUI floor printed as bare `dB` with no
  reference (`monitor_tui.rs:102`); `fmt_vrms` flips 3→4 decimals at the 1 V
  boundary.

**Working well:** `print_freq_row` typographic discipline (decimal-aligned, 78
cols); `monitor_tui.rs` (jitter-free fixed-width live refresh, NaN/-inf filtered);
unit explicitness in `dmm`/`calibrate`/`setup`; consistent lowercase
`  error:` register via `check_ack`; 80-col discipline throughout.

**Owner-resolved (2026-05-27):** noise floor → summary shows worst-case, per-point
behind `--verbose`; level frame → dBu when calibrated, else dBFS; timestamps →
unify on `%Y-%m-%dT%H:%M:%SZ` (compact `20260527T142208Z` for filenames, ordered
last, coordinated with daemon/ds); THD+N → both `%` and `dB re fund` in the CLI
summary.

## qa findings

Build: `cargo test --workspace` → **680 passed, 0 failed, 3 ignored**. All 7
standards PDFs read directly; digital-path checks done against full AES17-2020.

**Critical gaps (a measurement can be wrong and no test catches it):**
1. **THD+N denominator is the fundamental, not total signal level**
   (`thd.rs:118,107`) — off-spec vs AES17-2020 §6.3.1 and the cited IEC
   §15.12.3.2; untestable by the current pure-sine suite; doc comment's
   "bit-compatible" claim is inaccurate on the denominator.
2. **No producer↔consumer schema test** for the ZMQ monitor sidecar frames —
   silent runtime drift between ac-daemon and ac-ui.
3. **CCIR-468 quasi-peak detector unverified vs BS.468-4 Table 2** — weighting
   network is exact, but QP time constants (`ccir468.rs:191-195`) are hand-picked;
   steady-state-only tests can't catch a wrong ballistic.
4. **`ds` has zero tests** + two uncaught network failure modes
   (`URLError`/`socket.timeout` crash raw; `call_claude` has no timeout); no
   prompt caching despite re-sending full session context each call.

**Weak assertions to tighten:** dead test `thd.rs:308` (`let _ = result;`);
`filterbank.rs:342` returns flat 17.5 dB for every bpo (bpo-independent
neighbour-rejection test); `weighting.rs` evaluates filter at 31.0 Hz but
compares to 31.5 Hz reference (masked by tolerance); several one-sided bounds
(intersample peak, A-weighting@100Hz, CCIR burst).

**Standards labelling gaps:** no runtime weighting designator (`dBA`/`dBC`/`dBZ`)
or class label emitted (IEC 61672-1 requires it with the level); no
"1/3-octave" bandwidth-designator string; filterbank citation clause mismatch
(§5.4 vs §5.10); THD+N unit dB-vs-% standard ambiguity.

**Exemplary coverage (the model for the rest of the tree):** H1 transfer
estimator (`transfer.rs`) — analytic spot-checks, sample-exact delay, coherence
bounds, IR recovery; BS.1770-5 loudness — Annex-1 coeffs to 1e-6, Tech3341 cases,
true-peak, gating, LRA, correct LKFS/dBTP designations; CCIR-468 weighting
network (Table-1 full); scalar conversion/reference layer; Farina sweep.

## recommended issue order

Foundational/correctness first, then safety nets, then polish.

1. **Fix THD+N denominator to total signal level + add high-distortion test** —
   a wrong measurement value; everything else is cosmetic next to a wrong number.
2. **Add ac-daemon→ac-ui JSON round-trip test for monitor sidecar frames** —
   cheapest fix for the highest-brittleness defect; catches schema drift today.
3. **Hoist ZMQ frame structs into `ac-core` + version the Tier 2 envelope** —
   removes the triple-definition at the root; larger but unblocks safe frame edits.
4. **Refresh the stale module map + correct the H1 invariant wording** — stops the
   re-mapping tax and the "fix-correct-code" trap for every future contributor.
5. **Decide governing THD+N standard (dB vs %) and apply across report + CLI** —
   single ruling that unblocks both the qa relabel and the ux display fix.
6. **CLI run header + summary rework (timestamp, duration, noise floor, dB form)** —
   display-only, daemon already emits the data; biggest user-visible improvement.
7. **Document the `ds` session-dir file contract, then unify timestamps last** —
   sequenced after the contract exists, coordinated with daemon/ds owners.
8. **Test-hygiene sweep** — remove dead `thd.rs:308`, make `filterbank.rs:342`
   bpo-dependent, fix `weighting.rs` 31.0→31.5 Hz, add CCIR-468 burst tests, add
   minimal `ds` tests + network-error/timeout handling.

## what is working well

- **Crate architecture needs no refactor** — clean acyclic graph, single shared
  lib, no client cross-dependencies.
- **The DSP core is exemplary.** H1 transfer estimator and BS.1770-5 loudness are
  the model the rest of the tree should follow: analytic verification, locked
  coefficients, real conformance cases, correct standard designations.
- **Level-reference layer is correct and regression-safe** — scalar dBu, mic curve
  cleanly separated and applied post-measurement; matches the invariant exactly.
- **CLI typography is disciplined** — decimal-aligned, 80-col safe, consistent
  lowercase error register; `monitor_tui.rs` is genuinely good live-refresh code.
- **Test suite is green and broad** (680 passing) with strong standards grounding —
  the gaps are specific and known, not systemic.
- **Farina sweep path** is correctly derived and correctly cited.
