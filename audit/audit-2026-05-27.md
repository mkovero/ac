# codebase audit — 2026-05-27

## scope

Audited: the `ac-rs/` Cargo workspace — `ac-core` (shared lib), `ac-daemon`
(ZMQ server + audio), `ac-ui` (egui client), `ac-cli` (CLI client) — and the
standalone Python companion `ds/`. ~45k LOC. Three specialist passes:
architect (structure, boundaries, invariants), ux (all stdout/stderr output
surfaces), qa (test-coverage map + standards conformance against the 7
reference PDFs).

Out of scope: live hardware-in-the-loop verification on the test rig
(192.168.9.40); runtime performance/profiling; the egui visual layout of
`ac-ui` (only its text output was reviewed); third-party dependency audit.

Note: the spec/onboarding module map (`estimator.rs`, `level.rs`, `signal.rs`,
`thd_tool`, `ds/src/session.rs`) is **stale** — all three specialists audited
the real layout instead and flagged the drift independently.

## executive summary

The codebase is structurally healthy: a clean acyclic crate graph with a single
shared library, a correctly scalar (frequency-independent) level reference, and
genuinely exemplary test coverage in the DSP core (H1 transfer estimator and
BS.1770-5 loudness are model-grade). The dominant risk is not in the math — it
is in the **ZMQ wire contract**, which is defined three times (daemon inline
`json!()`, typed ac-ui structs, untyped ac-cli parsing) with no shared type and
no producer↔consumer test, so a field rename breaks the UI silently at runtime.
A secondary cluster of issues sits on the **CLI output surface and the THD+N
measurement**: the most diagnostic figures (noise floor, duration) are written
to disk but never shown, and THD+N uses the wrong denominator *and* an off-spec
label — a defect that is structurally invisible to the current tests because
they only feed pure sines. None of these are alarming; all are addressable
incrementally, and the foundational fix (single-sourcing the schema) unblocks
several others.

## cross-cutting findings

### [cross-cutting] ZMQ schema is triple-defined and has no producer↔consumer test
**areas:** architect + qa
**finding:** The wire schema lives in three places with no shared type — daemon
emits inline `json!()` frames, `ac-ui/data/types.rs` mirrors them as typed serde
structs, `ac-cli` parses untyped `serde_json::Value`. Agreement is manual,
documented only in `ZMQ.md` (51 KB). Architect ranks this the single most
brittle spot in the tree. QA confirms the matching gap from the test side: there
is **no round-trip test** that ac-ui deserializes the exact JSON ac-daemon emits
for the monitor sidecar frames (`momentary_lkfs`, `integrated_lkfs`, `dBTP`,
THD). Tier 2 / streaming frames are also unversioned (only `measurement/report`
carries `schema_version`).
**why it matters:** A field rename on either side compiles clean and fails
silently at runtime; `ZMQ.md` can drift from code freely. This is the highest
blast-radius defect class in the repo and it has zero compile-time *or* test-time
guard.
**suggested first step:** Hoist the frame structs into `ac-core`; have the daemon
serialize them and ui/cli deserialize them. A single shared type collapses the
triplication and makes the qa round-trip test trivial to add. Add a protocol
version field to the data envelope while the types are being moved.

### [cross-cutting] THD+N output is both off-spec and under-labelled
**areas:** ux + qa
**finding:** QA: `thd.rs` divides the residual by the **fundamental** (`f1_amp`),
but AES17-2020 §6.3.1 and IEC 60268-3 §15.12.3.2 (the clause the file cites)
both reference the ratio to **total signal level** — wrong as THD+N rises, and
structurally untestable by the current suite (every test feeds a pure/near-pure
sine where fundamental≈total). The unit is `%` while AES17-2020 prefers dB for
digital ratios. UX, from the display side: the `THD+N%` column carries no
reference (`re fund` missing), and the dB form — the more readable one at low
distortion — is never shown in the CLI.
**why it matters:** The same number is wrong (denominator), unlabelled (no
reference), and shown in the less-useful unit — and no test catches any of it.
A DUT with several-% THD+N reads low and a reader cannot tell what the figure is
relative to.
**suggested first step:** Fix the denominator to total signal level (or document
the deviation and relabel), then add a single high-distortion-with-noise test
pinning a known THD+N value. The ux relabel (`re fund`, dB-alongside-%) follows
naturally once the correct value and reference are decided.

### [cross-cutting] timestamp/filename unification collides with implicit ds file coupling
**areas:** ux + architect + qa
**finding:** UX found three timestamp formats coexisting and no ISO-8601
timestamp on any CLI run; the owner-approved fix unifies every surface and
filename on UTC `%Y-%m-%dT%H:%M:%SZ` (compact `20260527T142208Z` for filenames).
That **changes on-disk filenames**. Architect found that `ds` couples to `ac`
purely through on-disk file layout (`ds/files.py:9`, `ds/context.py:91` scan the
session dir for `.csv`/`.png`) with no schema and no test. QA confirms `ds` has
**zero tests**.
**why it matters:** A display-quality improvement (timestamp unification) reaches
across an undocumented, untested file-layout contract into a separate language
ecosystem. Changing `ac` output filenames silently breaks `ds` context
summaries with no compile error and no test failure on either side.
**suggested first step:** Before the filename cutover, document the session-dir
contract (or expose an `ac` command `ds` can call) and add a minimal `ds` test
that asserts it can find/parse current `ac` outputs. Sequence the timestamp work
**last** in the ux display series, gated on that.

### [cross-cutting] stale architecture map and misstated invariants
**areas:** architect + qa (ux unaffected — it audited reality directly)
**finding:** All specialists hit the same stale module model from the specs
(`estimator.rs`, `level.rs`, `signal.rs`, `thd_tool`, `ds/src/session.rs` —
none exist). Beyond the map, two named invariants are wrong: the "H1 =
Müller-Massarani" invariant is misstated (the live estimator is Welch-H1,
the sweep path is Farina — and `sweep.rs` already cites Farina correctly; no
"Müller"/"Massarani" string exists in code), and the qa-spec's claim that LUFS
is preferred per BS.1770-5 §3 is contradicted by the standard (it prescribes
LKFS, which the code correctly uses).
**why it matters:** A dev following the docs edits the wrong place or "fixes"
correct code toward a wrong derivation. Low blast radius today, but it taxes
every future onboarding and every issue that touches these modules.
**suggested first step:** Refresh the module map to the real 4-crate + Python
layout; correct the H1 invariant wording to cite Welch (live) and Farina (sweep)
explicitly; drop the LUFS claim.

## architect findings

> **Scope note:** spec module map is stale. Reality audited: 4-crate Rust
> workspace under `ac-rs/crates/` — `ac-core`, `ac-daemon`, `ac-ui`, `ac-cli` —
> plus standalone Python `ds/`. No `thd_tool` crate; THD is
> `ac-core/src/measurement/thd.rs`. ~45k LOC.

**Module boundaries.** Clean acyclic graph: `ac-core ← ac-daemon`,
`ac-core ← ac-ui`, `ac-core ← ac-cli`. `ac-core` depends on no sibling. No
circular deps; no client depends on another. `ds/` is Python, fully outside the
cargo workspace, coupled to `ac` by **on-disk file layout** (reads the session
dir for `.csv`/`.png`), not the wire protocol. One smell: wire-frame
construction is inline `json!()` in daemon handlers, while the typed mirror lives
in `ac-ui/src/data/types.rs` — the schema's two halves sit in two crates with no
shared type. Belongs in `ac-core`.

**Invariant audit.**
| invariant | enforced | notes |
|---|---|---|
| ZMQ schema single-sourced | ✗ | Triplicated: daemon inline `json!()`; ac-ui typed serde; ac-cli untyped `Value`. `ZMQ.md` (51 KB) is the only authority. |
| no freq-dependent level ref | ✓ | `shared/reference_levels.rs` + `conversions.rs` all scalar. Mic curve is a separate structure applied post-measurement, not baked into level ref. |
| H1 matches Müller-Massarani | ✗ | **Misstated.** Live `transfer.rs` is Welch H1=Gxy/Gxx (Hann, 50% overlap, coherence). `measurement/sweep.rs` is Farina exp-sweep deconvolution. Cited PDF is Farina 2000, not MM 2001 — and `sweep.rs` cites it correctly. No "Müller"/"Massarani" in code. |
| thd_tool standalone | ✓ (N/A) | No `thd_tool` crate. THD is a pure lib module in ac-core; no runtime coupling. |

**Interface surface.** ZMQ: REP ctrl `tcp://127.0.0.1:5556`, PUB data
`tcp://127.0.0.1:5557` (`PUB_HWM=50_000`). Data frames `<topic> <json>`; ctrl
replies carry `{"ok": bool, ...}`. **Only** Tier 1 `measurement/report` carries
`schema_version` (=3); all Tier 2 / streaming frames are unversioned. ac-ui uses
`#[serde(default)]` ~31× → additive forward-compat, but renamed/removed fields
still break. CLI: `ac-cli` clap subcommands, consistent style; `ds` has its own
Python CLI (separate surface, intentional). Undocumented assumptions: changing a
JSON key silently breaks ui deserialize while cli limps; changing `ac` output
filenames/layout breaks `ds` with no compile error.

**Structural risks (ranked):**
1. ZMQ schema triple-defined, no shared type, Tier 2 unversioned — most brittle
   spot. *Mitigation:* hoist frame structs into `ac-core`; version the envelope.
2. Stale architecture map vs reality — devs waste time / edit wrong place.
   *Mitigation:* refresh the map.
3. Misnamed H1 invariant — invites "fixing" correct code toward wrong
   derivation. *Mitigation:* cite Welch + Farina explicitly.
4. `ds`↔`ac` file-layout coupling is implicit, no schema, no test.
   *Mitigation:* document the session-dir contract or expose an `ac` command.

No significant dead code in level-ref / conversion paths; removed
freq-correction curve is genuinely gone.

## ux findings

Scope: all stdout/stderr paths under `ac-rs/`. CLI output is structured,
decimal-aligned, unit-aware in most places — sound foundation. But it misses the
baseline on three mandatory fields (timestamp, duration, noise floor), carries
forbidden decorative borders, and is inconsistent on dB precision / reference
labelling across tools.

**Consistency findings (selected):**
| tool | issue | severity |
|---|---|---|
| ac-cli | no ISO-8601 timestamp anywhere in terminal output | high |
| ac-cli | duration / averaging window never shown (only requested sweep dur echoed) | high |
| ac-cli | `noise_floor_dbfs` measured + written to CSV (`io.rs:14`) but never shown | high |
| ac-cli | `THD+N%` header carries no reference (`re fund`) | med |
| ac-cli | dB precision varies: `.1` sweep, `.2` dmm/calibrate, `.8` V setup | med |
| ac-cli | `[CLIP]`/`[AC]` inline at row end; baseline wants own line | med |
| ac-cli | `[PASS]`/`[FAIL]`/`SUMMARY` all-caps — shouty | low |
| ac-ui+cli | three timestamp formats coexist | med |
| ac-ui tui | floor printed as bare `dB`, no reference (`monitor_tui.rs:102`) | med |
| ac-core | `fmt_vrms` precision flips 3→4 decimals at 1 V boundary | low |

**Baseline deviations.** No timestamp on any run; no duration/averaging window;
noise floor hidden (the most diagnostic figure, written to disk and withheld —
violates the "tolerance for the minute" principle); decorative `=`/`─` borders
(`io.rs:92,94,139`) the spec forbids; inline warnings instead of own-line.

**What is working well.** `print_freq_row` decimal-aligns every column within 78
cols — exactly the discipline the spec asks. `monitor_tui.rs` is genuinely good
(fixed-width rows, prefers daemon THD fundamental, filters NaN/-inf, clears to
end). `dmm`/`calibrate`/`setup` state references and signs explicitly. Error
path register is consistent (`  error: <msg>` via `check_ack`). 80-col
discipline holds everywhere.

**Owner-resolved decisions (2026-05-27):** noise floor shows worst-case by
default, per-point column behind `--verbose`; display dBu when output
calibration exists, else dBFS; unify all surfaces+filenames on UTC
`%Y-%m-%dT%H:%M:%SZ` (compact form for filenames — **on-disk filenames change,
coordinate with daemon+ds owners**); THD+N in both `%` and `dB re fund` in the
summary. Implementation order: decoration/register fixes → run header + summary
rework → dBu-when-calibrated → `--verbose` column → timestamp unification last
(gated on ds coordination).

## qa findings

Build state: `cargo test --workspace` → **680 passed, 0 failed, 3 ignored**.
All 7 standard PDFs read directly. Digital-path checks done against full
AES17-2020 (the on-disk AES-17-2015 is a purchase-preview stub).

**Test coverage map (selected).**
- `transfer.rs` (H1) — **strongest in the tree**: unity loopback, pure delay,
  single-pole vs analytic z-transform, noise robustness, coherence bounds, IR
  recovery, re/im round-trip. No material weak assertions.
- ac-daemon→ac-ui session schema — `it_protocol.rs` exercises framing; **no
  round-trip test that ac-ui deserializes the exact daemon JSON** for sidecar
  frames. Drift uncaught.
- `thd.rs` — broad pure-sine + proptest coverage, but **no high-distortion
  THD+N test** (wrong denominator invisible); dead test at `thd.rs:308`
  (`let _ = result;` asserts nothing).
- `loudness.rs` (BS.1770-5) — **excellent**: Annex-1 coeffs 1e-6, Tech3341
  cases 1–4+9 to ±0.1 LU, true-peak FIR, gating, LRA.
- `ccir468.rs` — weighting network fully validated (Table 1, 20 pts); **QP
  detector NOT tested vs Table 2 burst tolerances** (time constants hand-picked).
- `weighting.rs` — A/C/Z vs Table 2; **test evaluates at 31.0 Hz but compares to
  31.5 Hz reference** (masked by tolerance, line 317/330).
- `filterbank.rs` — centres/gain validated; **`class1_neighbour_min_atten_db`
  returns flat 17.5 dB for every bpo** (line 342) — test weaker than its comment.
- `ds/session.py`, `ds/ai.py`, `ds/scraper.py` — **zero tests**.

**Standards conformance (key non-conformances).**
- THD+N denominator divides by fundamental, not total signal (AES17-2020 §6.3.1
  / IEC 60268-3 §15.12.3.2) — ✗.
- THD+N unit `%` where AES17-2020 prefers dB for digital ratios — ✗ partial.
- THD+N bandwidth sums to Nyquist with no §5.2.5 band-edge filter — ✗ minor.
- THD+N notch ±10% (Q≈5) narrower than standard min width (Q 1.2–3) — ?.
- A/C/Z and fractional-octave: values correct but **no runtime designator
  string** (`dBA`/`dBC`/`dBZ`, "1/3-octave") emitted — IEC requires it.
- Loudness LKFS, K-weighting, true-peak dBTP — ✓ (and the qa-spec's LUFS-preferred
  claim is contradicted by the standard; code is correct as-is).
- dBu scalar reference — ✓ regression-safe.

**Critical gaps (wrong + untestable by current suite):** (1) THD+N denominator;
(2) no ac-daemon→ac-ui schema round-trip test; (3) CCIR-468 QP detector
unverified vs BS.468-4 Table 2; (4) `ds` zero tests + uncaught network failure
modes (`URLError`/`socket.timeout` crash, no request timeout, no prompt caching).
