## ux audit — 2026-05-27

Scope: all stdout/stderr-producing paths under `ac-rs/` (`ac-cli`, `ac-daemon`,
`ac-ui` text output, `ac-core` shared formatters). Read-only.

The CLI output is structured, decimal-aligned, and unit-aware in most places —
the foundation is sound. But it misses the `ac` CLI baseline on three mandatory
fields (timestamp, duration, noise floor), carries decorative borders the spec
forbids, and is inconsistent on dB precision and reference labelling across the
three tools.

---

### consistency findings

| tool | field | issue | severity |
|---|---|---|---|
| ac-cli | (all measurement runs) | no ISO-8601 timestamp anywhere in terminal output; baseline requires one per run | high |
| ac-cli | duration / averaging window | never shown in plot/test summary; only the *requested* sweep duration is echoed, never elapsed/averaging | high |
| ac-cli | noise floor | `noise_floor_dbfs` is measured and written to CSV (`io.rs:14`) but never shown on screen | high |
| ac-cli | THD+N column | header `THD+N%` (`io.rs:168`) carries no reference; baseline wants `re fund` | med |
| ac-cli | dB precision | dBu shown `.1` in sweep/plot headers (`sweep.rs:21`), `.2` in dmm/calibrate, `.8` V in setup — no shared decimal discipline | med |
| ac-cli | clip/AC warnings | `[CLIP]`/`[AC]` rendered inline at row end (`io.rs:200`), baseline says condition warnings go on their own line | med |
| ac-cli | self-test marks | `[PASS]`/`[FAIL]` all-caps (`test.rs:18`); `SUMMARY` all-caps (`io.rs:93`) — shouty, off-register | low |
| ac-ui / ac-cli | timestamp format | three formats coexist: filename `%Y%m%d_%H%M%S` local no-tz (`io.rs:160`, `export.rs:27`), `to_rfc3339` (`sweep.rs:216`), `%Y-%m-%dT%H:%M:%SZ` (`plot.rs:26`) | med |
| ac-ui (tui) | floor unit | floor printed as bare `dB` (`monitor_tui.rs:102`) with no reference (dBFS? re peak?) | med |
| ac-core | fmt_vrms | precision flips 3→4 decimals at the 1 V boundary (`conversions.rs`); a 0.999 V and 1.001 V reading print at different resolution | low |

### baseline deviations

The `ac` CLI baseline mandates, on every measurement run: type + signal
conditions, primary result with unit+reference, noise floor, duration/averaging
window, ISO-8601 timestamp, warnings on their own line.

- **No timestamp on any run.** Grep for `rfc3339|%Y-%m-%dT|Local::now|Utc::now`
  finds timestamps only in filenames and embedded report JSON. No `ac plot`,
  `ac test`, `ac calibrate`, `ac generate` terminal output carries one.
  `io.rs:159` `timestamp()` exists but is filename-only (`%Y%m%d_%H%M%S`,
  local, no tz). — **fix: add ISO-8601 UTC header line to every run.**
- **No duration / averaging window shown.** `sweep.rs:21,55,95` echo the
  *requested* duration in the pre-run line; `plot.rs` and `test.rs` summaries
  show none, and nothing reports elapsed or averaging count. — **fix: add
  `duration` (and averaging state where applicable) to the summary block.**
- **Noise floor hidden.** `io.rs:14` lists `noise_floor_dbfs` as a CSV column,
  so the daemon already reports it per point — but `print_freq_row`
  (`io.rs:189`) and `print_summary` (`io.rs:47`) never display it. The quietest,
  most diagnostic figure is written to disk and withheld from the eye. This is
  the "tolerance for the minute" principle violated directly. — **fix: surface
  worst-case / median noise floor in the summary.**
- **Decorative borders.** `print_summary` brackets the block with
  `"=".repeat(62)` top and bottom (`io.rs:92,139`) plus a `─` rule (`io.rs:94`).
  Spec: never box, prefer whitespace to separator lines. `monitor_tui.rs:121`
  uses two `─`.repeat(69) bars per frame — tolerable for a live-refresh frame
  (brackets a changing region) but still heavier than needed.
- **Inline warnings.** `[CLIP]`/`[AC]` flags ride the end of each data row
  (`io.rs:200-206,231`). Baseline wants signal-condition warnings on their own
  line. In tabular per-point output a column flag is defensible, but the run
  should still emit a separate summary warning line (it currently only counts
  them in `print_summary`).

Reasonable exceptions (not flagged for change):
- Daemon stderr (`gpio:`, `plot:`, `ac-daemon:` prefixes) is a log surface, not
  the user result surface — a different register is fine there.
- `fmt_vrms` auto mV/V switch aids readability; only the decimal-count flip is
  the nit.

### unit / label gaps

- `monitor_tui.rs:102` — floor `{:>5.0} dB`: no reference. Is this dBFS, or dB
  re peak? Ambiguous. Should be `dBFS` (matches the peak on the same row).
- `io.rs:168` — `THD+N%` column: `%` is attached to the label (acceptable per
  spec's THD exception) but the implicit `re fundamental` reference is absent.
- `test.rs:18` — self-test `detail` string is free-form daemon text; no unit
  contract. Low risk but unverifiable from the format string.
- Everywhere THD+N is shown alongside a dB figure, only `%` appears — the
  baseline example pairs it: `0.0023 %   –92.8 dB re fund`. The dB form is
  never shown in CLI even though it is the more readable form at low distortion.

What is already correct:
- `dmm.rs` — `Vrms = dBu = Vpp` triple with explicit units and sign on dBu. Good.
- `calibrate.rs:105` — `0 dBFS = <vrms> = <dbu> dBu`, reference stated. Good.
- `setup.rs:119` — dBu reference shown as mVrms *and* exact volts (`.8`). Honest
  about the minute.

---

### information hierarchy issues

- The single most diagnostic number — noise floor — is absent from screen while
  `Average THD` (a less informative aggregate) gets a dedicated summary line
  (`io.rs:109`). The aggregate is louder than the signal.
- `SUMMARY -- {device}` in all-caps inside a `===` box (`io.rs:92-94`) is the
  heaviest-weighted element on screen, yet it carries no measurement value —
  pure structural label. It outweighs the numbers it introduces.
- `print_freq_header` (`io.rs:163`) renders a full dashed rule under every
  column on every run. The rule competes with the data rows for weight; column
  alignment alone already separates header from body.

---

### structural / colour issues

- No ANSI colour is used anywhere in CLI output. This trivially satisfies
  "readable with colour disabled" and the plain-text mandate — but leaves the
  ember accent (term 173) unused on the one value that should glow (the primary
  result / the noise-floor anomaly). Opportunity, not a defect: colour must stay
  a non-sole enhancement layered over the already-complete plain text.
- `=`/`─` repeat borders (`io.rs:92,94,139`; `test.rs:12`; `probe.rs:11`;
  `monitor_tui.rs:121`) are the main decorative debt. Replace with blank-line
  grouping per the spec's "sparse spacing beats separator lines".
- Three timestamp formats across the codebase is a structural inconsistency
  even though only one (the absent CLI one) is a baseline miss.

---

### what is working well

- `print_freq_row` (`io.rs:189`) decimal-aligns every numeric column, right-
  justifies values, left-justifies labels — exactly the typographic discipline
  the spec asks for, and holds within 78 cols.
- `monitor_tui.rs` is genuinely good: fixed-width rows so live refresh doesn't
  jitter, prefers daemon's THD fundamental over a raw bin scan, filters NaN/-inf
  from the floor, clears-to-end so a dropped channel leaves no stale line. The
  trace-not-point intent is respected.
- Unit explicitness in `dmm`, `calibrate`, `setup` is strong — references stated,
  signs shown, no bare numbers.
- Error path register is consistent in CLI: `  error: <msg>` lowercase, 2-space
  indent, across every command via `check_ack` (`mod.rs:71`).
- 80-column discipline holds everywhere; nothing assumes terminal width.

### proposed display improvements (top 3)

#### 1 — add the mandatory header (timestamp + signal + duration) to every run

`ac plot` / `ac test dut` currently jump straight into the table with no run
context. Add the baseline header.

```
before:
  Loaded calibration from server.

  Plot: 20 → 20000 Hz  10 pts/decade  |  -10.0 dBFS
  ──────────────────────────────────────────────────────────────────────────────
     Freq      Out Vrms   Out dBu       In Vrms    In dBu      Gain       THD%     THD+N%

after:
ac plot  2026-05-27T14:22:08Z

signal      20 Hz – 20 kHz   –10.0 dBu   10 pts/decade
calibration server  (1 kHz, scalar)

     Freq      Out Vrms   Out dBu       In Vrms    In dBu      Gain      THD%   THD+N re fund

removed: the `=`/`─` decorative rule under the header; the "Loaded calibration"
         status line folded into a single `calibration` field
added:   ISO-8601 UTC timestamp (baseline-mandatory); explicit signal line
changed: dBFS→dBu where calibration exists (re fundamental is the user's frame,
         not the converter's); THD+N column gains its `re fund` reference
```

#### 2 — surface noise floor and duration in the summary; drop the box

The measured noise floor is the signal the long-exposure eye is here for, and
it is currently written only to CSV. Promote it; demote the decorative frame.

```
before:
==============================================================
  SUMMARY -- DUT
──────────────────────────────────────────────────────────────
  Levels measured:  21
  Worst THD:        0.0041%
  Worst THD+N:      0.0089%
  Average THD:      0.0023%
==============================================================

after:
summary  DUT                              21 levels   4.1 s

THD          worst 0.0041 %   median 0.0021 %
THD+N        worst 0.0089 %   (–81.0 dB re fund)
noise floor  –94.1 dBFS  (min across sweep)

removed: the two `===` borders and the `─` rule (decoration, no information);
         the all-caps `SUMMARY` shout
added:   noise-floor line (was CSV-only — the most diagnostic figure); duration
         on the title line; THD+N in dB re fund alongside %
changed: median replaces "Average" (robust to clip/AC outliers); blank-line
         grouping replaces box; lowercase `summary` matches the run-header register
```

#### 3 — give the TUI floor a reference and put condition warnings on their own line

```
before:
CH0    peak   -3.0 dBFS @    1000 Hz   floor   -85 dB

after:
CH0    peak   –3.0 dBFS @  1000 Hz   floor  –94.1 dBFS
       ! AC-coupled — coupling-cap rolloff below 20 Hz

removed: bare `dB` floor unit
added:   `dBFS` reference on floor (matches peak's frame on the same row);
         a dedicated warning line under the channel when a condition is flagged
changed: floor precision .0 → .1 — at –94 dB the tenths are where the minute lives
```

### resolved decisions (2026-05-27, project owner)

1. **Noise floor:** summary shows worst-case (min across sweep) by default;
   per-point `noise_floor_dbfs` column gated behind `--verbose`. Default table
   stays ≤ 80 cols with calibration on. — improvement #2 stands as proposed;
   `--verbose` adds the per-row column.
2. **Level frame:** display **dBu when output calibration exists**, fall back to
   dBFS uncalibrated. — improvement #1's `dBFS → dBu` swap is confirmed correct.
3. **Timestamps:** unify **every surface and filename** on
   `%Y-%m-%dT%H:%M:%SZ` UTC. Touches `io.rs:160` (`timestamp()`),
   `export.rs:27`, `sweep.rs:216`, `plot.rs:26`, and on-disk filename
   generation. **On-disk filenames change** — coordinate the cutover with the
   daemon + ds owners (existing files keep old names; only new writes change).
   Note: filesystem-unsafe `:` in the timestamp — use the compact UTC form
   `20260527T142208Z` for filenames, full `2026-05-27T14:22:08Z` for terminal.
4. **THD+N in dB re fund:** lives in the **`ac` CLI summary** (both `%` and
   `dB re fund`), per improvement #2. Not pushed to per-point rows; `ds` keeps
   its own structured display. dB is the readable form at low distortion.
